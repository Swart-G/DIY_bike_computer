# PLAN.md

План разработки прошивки велоспидометра.

## Общая стратегия

Сначала поднимается железо и диагностический интерфейс, потом логика заезда, потом запись данных. Нельзя начинать с полноценного красивого интерфейса, пока не проверены экран, тач, SD и USB.

Проект разрабатывается на PlatformIO + Arduino framework для ESP32-S3-N16R8.

## Текущая цель первого тестового варианта

Сделать прошивку, которая:

- запускается на ESP32-S3-N16R8;
- инициализирует ST7796 TFT;
- включает подсветку;
- инициализирует FT6336 touch;
- показывает главное меню;
- имеет настройки/диагностику;
- содержит Paint-тест;
- обнаруживает SD-карту;
- создаёт и читает тестовый текстовый файл на SD;
- отдаёт SD-карту компьютеру как USB Mass Storage;
- показывает тест датчика на GPIO4;
- содержит заглушку измерителя батареи;
- не падает без SD, без датчика и без батарейного измерителя.

## Phase 0 — Подготовка репозитория

Задачи:

- создать `platformio.ini`;
- создать базовую структуру `src/`;
- создать конфиги `hardware_config.h` и `app_config.h`;
- вынести все GPIO в `hardware_config.h`;
- добавить в README инструкцию сборки;
- проверить, что пустая прошивка собирается.

Критерий готовности:

- `pio run` проходит без ошибок;
- Serial выводит сообщение старта прошивки.

## Phase 1 — Boot, Serial, базовый runtime

Задачи:

- настроить Serial debug;
- вывести информацию о плате, Flash, PSRAM, частоте CPU;
- проверить доступность PSRAM;
- добавить системный экран ошибки/загрузки;
- добавить простую систему логирования в Serial.

Критерий готовности:

- при старте в Serial видно версию прошивки, параметры памяти и результат init-этапов.

## Phase 2 — TFT ST7796

Задачи:

- выбрать и подключить библиотеку TFT;
- настроить SPI-пины:
  - MOSI GPIO11;
  - SCK GPIO12;
  - MISO GPIO13;
  - LCD_CS GPIO10;
  - LCD_DC GPIO9;
  - LCD_RST GPIO14;
  - LCD_BL GPIO47;
- инициализировать экран ST7796;
- сделать экран загрузки;
- сделать тест цветов;
- проверить ориентацию экрана;
- добавить управление яркостью подсветки, если возможно через PWM.

Критерий готовности:

- экран показывает текст;
- цвета выводятся правильно;
- подсветка включается;
- ориентация удобна для корпуса.

## Phase 3 — Touch FT6336

Задачи:

- настроить I2C:
  - SDA GPIO8;
  - SCL GPIO18;
  - RST GPIO17;
  - INT GPIO16;
- инициализировать FT6336;
- сделать raw touch test;
- вывести координаты касания на экран;
- проверить корректное преобразование координат под выбранную ориентацию экрана.

Критерий готовности:

- касание определяется;
- координаты соответствуют месту касания;
- кнопки UI можно нажимать пальцем.

## Phase 4 — UI shell и главное меню

Задачи:

- создать базовый UI manager;
- реализовать навигацию между экранами;
- сделать главное меню;
- сделать экран настроек;
- сделать верхнюю кнопку выхода в меню/настройки;
- сделать нижнюю панель кнопок для режима заезда.

Минимальные пункты главного меню:

```text
Ride
Diagnostics
Settings
USB Storage
About
```

Критерий готовности:

- через тач можно перейти во все основные разделы;
- есть кнопка возврата назад;
- UI не зависает при быстрых касаниях.

## Phase 5 — Диагностика экрана и тача

Задачи:

- экран теста цветов;
- экран теста шрифтов/размеров текста;
- экран теста линий/примитивов;
- Paint-тест:
  - рисование пальцем;
  - кнопка очистки;
  - кнопка назад;
- raw touch test:
  - x/y;
  - количество касаний;
  - состояние INT;
  - время последнего касания.

Критерий готовности:

- Paint-тест пригоден для проверки всей активной области экрана;
- raw touch test показывает стабильные координаты.

## Phase 6 — SD-карта

Задачи:

- настроить SD по SPI:
  - SCK GPIO12;
  - MOSI GPIO11;
  - MISO GPIO13;
  - SD_CS GPIO15;
- сделать обнаружение SD;
- показать статус SD на экране;
- при отсутствии SD показать:
  - `Retry`;
  - `Continue without saving`;
- создать тестовый файл;
- записать тестовый текст;
- прочитать файл обратно;
- показать результат на экране.

Тестовый файл:

```text
/BIKE_SPEEDOMETER_SD_TEST.txt
```

Критерий готовности:

- SD обнаруживается;
- файл создаётся;
- текст читается обратно;
- без SD прошивка продолжает работать.

## Phase 7 — USB Mass Storage

Задачи:

- настроить native USB ESP32-S3 через GPIO19/GPIO20;
- реализовать режим `USB Storage`;
- отдавать SD-карту компьютеру как Mass Storage;
- при входе в USB Storage остановить любые операции записи на SD из прошивки;
- показать экран активного USB режима;
- защититься от одновременного доступа прошивки и ПК к файловой системе.

Критерий готовности:

- при подключении к ПК устройство определяется как накопитель;
- виден тестовый файл с SD;
- после USB-режима можно безопасно перезагрузить устройство и снова увидеть SD в прошивке.

## Phase 8 — Тест датчика на GPIO4

Задачи:

- настроить GPIO4 как вход;
- сделать конфиг полярности датчика;
- добавить программный debounce/минимальный интервал между импульсами;
- считать импульсы через interrupt;
- показывать:
  - текущее состояние пина;
  - число импульсов;
  - время с последнего импульса;
  - текущий рассчитанный RPM;
  - текущую скорость, если задана окружность колеса.

Критерий готовности:

- замыкание/имитация сигнала меняет состояние на экране;
- импульсы считаются;
- прошивка не зависает при дребезге.

## Phase 9 — SpeedCalculator

Задачи:

- реализовать расчёт скорости по времени между импульсами;
- реализовать предполагаемую скорость при отсутствии новых импульсов;
- добавить порог остановки 3 км/ч;
- вынести окружность колеса в конфиг;
- добавить тестовый режим с программной генерацией импульсов только для внутренной проверки кода, без отдельного пункта меню mock sensor.

Критерий готовности:

- скорость растёт/падает ожидаемо;
- при остановке через некоторое время становится 0;
- порог 3 км/ч работает.

## Phase 10 — Ride state machine

Задачи:

- реализовать состояния:
  - `IDLE`;
  - `RIDING`;
  - `PAUSED`;
  - `FINISHED`;
- реализовать кнопки:
  - `Start`;
  - `Pause`;
  - `Resume`;
  - `Stop/Finish`;
- при перезагрузке во время активного заезда восстанавливать его в состоянии `PAUSED`;
- сохранить минимальный recovery-файл на SD, если SD доступна.

Критерий готовности:

- заезд можно начать, поставить на паузу, продолжить и завершить;
- после аварийной перезагрузки активный заезд не теряется полностью, а открывается как paused.

## Phase 11 — Ride UI

Задачи:

- реализовать основной экран заезда;
- сделать перелистываемые центральные страницы:
  - скорость;
  - график скорости;
  - статистика;
- нижняя панель:
  - Start;
  - Pause/Resume;
  - Stop/Finish;
- верхняя правая кнопка — меню/настройки;
- добавить статус SD, батареи и USB.

Критерий готовности:

- скорость крупно читается на велосипеде;
- график обновляется;
- статистика отображает max, avg, distance, duration;
- кнопки доступны пальцем.

## Phase 12 — Settings и config-файл

Задачи:

- создать `/config/bike_config.json`;
- при отсутствии файла создавать значения по умолчанию;
- сделать редактирование настроек через UI;
- минимум настроек:
  - окружность колеса;
  - порог остановки;
  - яркость;
  - полярность датчика;
  - интервал обновления UI;
  - параметры делителя батареи, когда будет выбран ADC-пин.

Критерий готовности:

- настройки сохраняются на SD;
- после перезагрузки настройки применяются.

## Phase 13 — Логирование заезда

Формат логирования пока не финализирован. На этом этапе использовать `docs/LOG_FORMAT.md` как предварительную рекомендацию.

Задачи:

- создать папку заезда;
- писать периодические samples;
- писать события start/pause/resume/finish;
- писать summary после завершения;
- не терять текущий заезд при перезагрузке.

Критерий готовности:

- после завершения заезда на SD есть файлы с данными;
- данные можно открыть на компьютере после USB MSC.

## Phase 14 — Battery monitor

Задачи после выбора ADC GPIO и номиналов делителя:

- включить `BATTERY_MONITOR_ENABLED`;
- читать ADC;
- пересчитывать напряжение аккумулятора;
- показывать voltage и raw ADC;
- добавить калибровку;
- добавить предупреждение низкого заряда.

Критерий готовности:

- напряжение на экране близко к мультиметру после калибровки.

## Phase 15 — Полировка и устойчивость

Задачи:

- обработка ошибок SD;
- обработка ошибок touch;
- watchdog-friendly main loop;
- отсутствие блокирующих задержек в UI;
- нормальная работа без SD;
- нормальная работа без датчика;
- нормальная работа с пустым/битым config-файлом;
- понятные сообщения ошибок на экране.

Критерий готовности:

- устройство можно использовать как автономный велокомпьютер;
- тестовые экраны остаются доступными для диагностики.
