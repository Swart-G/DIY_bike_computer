# FIRMWARE_SPEC.md

Полное техническое задание на прошивку велоспидометра.

## 1. Назначение прошивки

Прошивка должна превратить ESP32-S3 с TFT-экраном, тачем, SD-картой и проводным датчиком Холла в автономный велокомпьютер.

Устройство должно работать без телефона как основного дисплея. Bluetooth/Wi-Fi не являются обязательными для первого этапа.

## 2. Платформа

Использовать:

```text
PlatformIO
Arduino framework
ESP32-S3-N16R8
16 MB Flash
8 MB PSRAM
```

Экран:

```text
3.5" SPI TFT
Driver: ST7796
```

Тач:

```text
FT6336 over I2C
```

SD:

```text
SPI microSD
```

USB:

```text
ESP32-S3 native USB
Mass Storage mode for SD card
GPIO19/GPIO20
```

## 3. Общие требования

Прошивка должна:

- запускаться без SD-карты;
- запускаться без подключённого датчика Холла;
- запускаться без подключённого измерителя батареи;
- показывать понятные ошибки на экране;
- не зависать при ошибках периферии;
- иметь главное меню;
- управляться через тач;
- иметь диагностические экраны;
- сохранять настройки на SD, если SD доступна;
- использовать значения по умолчанию, если SD или config недоступны.

## 4. Boot sequence

При старте прошивка должна выполнять этапы:

1. Инициализация Serial debug.
2. Вывод версии прошивки в Serial.
3. Проверка Flash/PSRAM.
4. Настройка GPIO.
5. Инициализация подсветки.
6. Инициализация TFT.
7. Показ splash/loading экрана.
8. Инициализация touch FT6336.
9. Инициализация SD.
10. Загрузка config-файла, если SD доступна.
11. Инициализация датчика Холла на GPIO4.
12. Инициализация батарейного монитора, если включён.
13. Проверка recovery-файла активного заезда.
14. Переход в главное меню или экран восстановления заезда.

Если SD не обнаружена, показать экран:

```text
SD card not found
Ride logging disabled

[Retry]
[Continue without saving]
```

Поведение:

- `Retry` повторяет попытку инициализации SD;
- `Continue without saving` запускает интерфейс без записи данных;
- режим заезда доступен, но логирование отключено;
- в статусной строке должен быть индикатор `NO SD`.

## 5. Главное меню

Главное меню должно содержать минимум:

```text
Ride
Diagnostics
Settings
USB Storage
About
```

### Ride

Переход к экрану заезда.

### Diagnostics

Переход к тестам железа.

### Settings

Переход к настройкам устройства.

### USB Storage

Включение режима USB Mass Storage для SD-карты.

### About

Информация:

- версия прошивки;
- плата;
- Flash/PSRAM;
- драйвер дисплея;
- состояние SD;
- состояние touch;
- состояние battery monitor;
- build date/time, если доступно.

## 6. Экран заезда

Экран заезда должен иметь три зоны.

### Верхняя зона

- статус SD;
- статус батареи или `Battery: N/A`;
- статус текущего состояния заезда;
- кнопка меню/настроек справа сверху.

### Центральная зона

Перелистываемые страницы:

1. **Speed page**
   - крупная текущая скорость;
   - единицы `km/h`;
   - небольшой блок distance/time.

2. **Graph page**
   - график скорости за последние N секунд;
   - текущая скорость;
   - шкала времени;
   - шкала скорости или автоматическое масштабирование.

3. **Stats page**
   - текущая скорость;
   - max speed;
   - avg speed;
   - ride distance;
   - ride duration;
   - moving time;
   - pause time, если реализовано.

Переключение страниц:

- свайпом влево/вправо;
- или кнопками/точками страниц, если свайп сложен.

### Нижняя зона

Кнопки:

```text
[Start] [Pause/Resume] [Stop/Finish]
```

Поведение кнопок зависит от состояния заезда.

## 7. Состояния заезда

Использовать state machine:

```text
IDLE
RIDING
PAUSED
FINISHED
```

### IDLE

Заезд не начат.

Экран:

- скорость может отображаться как live speed без записи;
- distance = 0;
- avg = 0;
- duration = 0.

Кнопки:

- `Start` активна;
- `Pause` неактивна;
- `Stop` неактивна.

### RIDING

Идёт заезд.

Поведение:

- скорость считается;
- distance увеличивается по импульсам/расчёту оборотов;
- max speed обновляется;
- avg speed обновляется;
- duration идёт;
- данные пишутся на SD, если SD доступна и логирование включено.

Кнопки:

- `Start` неактивна или заменена на `Resume` только после паузы;
- `Pause` активна;
- `Stop/Finish` активна.

### PAUSED

Заезд поставлен на паузу.

Поведение:

- запись samples остановлена или помечается как paused;
- distance не увеличивается;
- avg speed не пересчитывается от паузного времени;
- live speed можно показывать отдельно, но она не должна влиять на статистику заезда;
- состояние должно сохраняться в recovery-файле.

Кнопки:

- `Resume` активна;
- `Stop/Finish` активна.

### FINISHED

Заезд завершён.

Поведение:

- запись логов закрыта;
- summary сохранён, если SD доступна;
- recovery-файл удалён или помечен как finished;
- можно показать экран итогов.

Кнопки:

- `New ride`;
- `Back to menu`.

## 8. Восстановление после перезагрузки

Если устройство перезагрузилось во время `RIDING` или `PAUSED`, после старта нужно восстановить заезд в состоянии `PAUSED`.

Экран восстановления:

```text
Unfinished ride found
Recovered as paused

[Resume]
[Finish]
[Discard]
```

Требования:

- автоматически не продолжать запись после перезагрузки;
- не терять уже накопленные distance/time/max/avg, если они были сохранены;
- если SD недоступна, восстановление возможно только из внутренней памяти, если такая реализация будет добавлена. Для первого этапа допустимо восстановление только при доступной SD.

## 9. Расчёт скорости

### Входные данные

- импульсы датчика Холла на GPIO4;
- окружность колеса из config;
- время между импульсами;
- текущее время `millis()` или `esp_timer`.

### Базовая формула

```text
speed_mps = wheel_circumference_m / delta_time_s
speed_kmh = speed_mps * 3.6
```

### Логика предполагаемой скорости

Если новый импульс ещё не пришёл, прошивка не должна продолжать показывать старую скорость бесконечно.

Правило:

- есть последний интервал между двумя импульсами: `last_pulse_interval_ms`;
- есть время с последнего импульса: `time_since_last_pulse_ms`;
- если `time_since_last_pulse_ms <= last_pulse_interval_ms`, можно удерживать последнюю рассчитанную скорость;
- если `time_since_last_pulse_ms > last_pulse_interval_ms`, нужно считать предполагаемую скорость так, будто новый оборот завершился сейчас:

```text
estimated_speed = wheel_circumference / time_since_last_pulse
```

Если `estimated_speed < stop_threshold_kmh`, скорость считается равной 0.

Порог по умолчанию:

```text
stop_threshold_kmh = 3.0
```

### Debounce / фильтрация

Добавить минимальный интервал между валидными импульсами:

```text
min_pulse_interval_ms = configurable
```

Назначение:

- защита от дребезга;
- защита от ложных импульсов;
- защита от невозможных скоростей.

Если импульс пришёл слишком рано, игнорировать его и увеличить счётчик `rejected_pulses`.

### Полярность датчика

Сделать настройку:

```text
sensor_active_level = LOW | HIGH
sensor_interrupt_edge = FALLING | RISING | CHANGE
```

Для первого варианта можно выбрать безопасное значение по умолчанию и дать поменять в настройках.

## 10. Расчёт статистики заезда

Показатели:

- current speed;
- max speed;
- avg speed;
- ride distance;
- elapsed duration;
- moving time;
- pause time.

Рекомендованная логика:

- `elapsed duration` — время от старта до текущего момента, включая паузы;
- `moving time` — только время в состоянии `RIDING`;
- `avg speed` — `ride_distance / moving_time`;
- пауза не должна ухудшать среднюю скорость;
- `max speed` обновляется только в `RIDING`.

## 11. Настройки

Настройки должны храниться на SD в файле:

```text
/config/bike_config.json
```

Если SD недоступна, использовать настройки по умолчанию из прошивки.

Минимальные настройки:

```json
{
  "wheel_circumference_m": 2.194,
  "stop_threshold_kmh": 3.0,
  "ui_update_interval_ms": 200,
  "log_sample_interval_ms": 1000,
  "sensor_pin": 4,
  "sensor_active_level": "LOW",
  "sensor_interrupt_edge": "FALLING",
  "min_pulse_interval_ms": 50,
  "display_brightness_percent": 80,
  "graph_window_seconds": 60,
  "battery_monitor_enabled": false,
  "battery_adc_pin": null,
  "battery_divider_r_top_ohm": null,
  "battery_divider_r_bottom_ohm": null
}
```

Требования:

- файл можно менять через настройки на экране;
- при повреждённом config-файле прошивка должна предложить восстановить defaults;
- значения должны валидироваться;
- GPIO из config не должны позволять случайно переназначить занятые пины без явного developer mode.

## 12. Диагностика

Раздел `Diagnostics` должен содержать:

```text
Display test
Touch raw test
Paint test
SD test
USB Mass Storage test
Sensor test
Battery test
System info
```

### Display test

Функции:

- заливка красным/зелёным/синим/белым/чёрным;
- тест текста;
- тест линий;
- тест прямоугольников;
- тест ориентации.

### Touch raw test

Показывать:

- x/y;
- количество касаний;
- состояние INT;
- время последнего касания;
- кнопку назад.

### Paint test

Функции:

- рисование пальцем;
- очистка экрана;
- отображение текущих координат;
- кнопка назад.

Назначение:

- проверить тач;
- проверить совпадение координат тача и экрана;
- проверить отрисовку.

### SD test

Функции:

- обнаружить SD;
- показать тип/размер, если доступно;
- создать файл `/BIKE_SPEEDOMETER_SD_TEST.txt`;
- записать тестовый текст;
- прочитать файл обратно;
- показать результат.

Пример текста:

```text
Bike Speedometer SD test
If you can read this file, SD write/read works.
```

### USB Mass Storage test

Функции:

- включить USB MSC;
- отдать SD-карту компьютеру;
- показать предупреждение о запрете записи прошивкой;
- показать инструкцию отключения.

### Sensor test

Показывать:

- GPIO number;
- current pin level;
- active level;
- interrupt edge;
- pulse count;
- rejected pulse count;
- last pulse time;
- interval between pulses;
- calculated speed.

### Battery test

Пока измеритель батареи не подключён:

```text
Battery monitor: disabled
ADC pin: not configured
```

После выбора ADC-пина:

- raw ADC;
- voltage at ADC;
- calculated battery voltage;
- calibration coefficient.

### System info

Показывать:

- firmware version;
- build date;
- free heap;
- PSRAM status;
- SD status;
- USB status;
- display driver;
- touch status.

## 13. SD и файлы

Текущий обязательный тестовый файл:

```text
/BIKE_SPEEDOMETER_SD_TEST.txt
```

Полноценный формат логов будет уточняться позже. Предварительные рекомендации находятся в `docs/LOG_FORMAT.md`.

Требования к первому этапу:

- SD detection;
- create test file;
- read test file;
- show result;
- expose SD over USB MSC.

## 14. USB Mass Storage

Режим должен быть доступен из:

```text
Main menu -> USB Storage
Diagnostics -> USB Mass Storage test
```

При входе в режим:

1. Остановить логирование.
2. Закрыть открытые файлы.
3. Заблокировать любые записи прошивки на SD.
4. Поднять USB MSC.
5. Показать экран:

```text
USB Storage Active
SD card is exposed to computer
Do not start ride logging now

Disconnect safely on computer first
[Reboot]
```

Для первого варианта допустимо выходить из USB MSC через перезагрузку устройства.

## 15. Ошибки и устойчивость

Прошивка не должна падать при:

- отсутствии SD;
- отсутствии touch;
- отсутствии датчика;
- отключенном battery monitor;
- битом config-файле;
- невозможности создать тестовый файл;
- невозможности прочитать файл;
- ошибке USB MSC.

Каждая ошибка должна иметь:

- сообщение на экране;
- запись в Serial;
- возможность продолжить, если это безопасно.

## 16. Производительность

Требования:

- UI не должен блокировать обработку импульсов датчика;
- ISR датчика должен быть минимальным;
- отрисовка графика не должна вызывать заметные зависания;
- запись на SD должна быть буферизованной;
- частые `delay()` в основном цикле запрещены;
- использовать неблокирующую архитектуру через `millis()`/timers.

## 17. Критерии готовности первого тестового варианта

Первый тестовый вариант готов, если:

- прошивка собирается;
- экран показывает главное меню;
- тач работает;
- Paint-тест работает;
- SD обнаруживается;
- тестовый файл создаётся и читается;
- USB MSC показывает SD на компьютере;
- GPIO4 тестируется как вход датчика;
- отсутствие SD не ломает устройство;
- отсутствие датчика не ломает устройство;
- батарейный монитор корректно отключён;
- старт/пауза/стоп заезда доступны в UI хотя бы без финального логирования.

## 18. Критерии готовности полноценной версии

Полная версия готова, если:

- скорость считается от реального датчика;
- скорость корректно падает до 0 при остановке;
- график скорости работает;
- max speed работает;
- avg speed работает;
- distance работает;
- duration/moving time работают;
- заезд пишется на SD;
- после завершения есть summary;
- после перезагрузки активный заезд восстанавливается как paused;
- настройки можно менять с экрана;
- SD можно открыть на ПК как флешку;
- устройство можно использовать как самостоятельный велокомпьютер.
