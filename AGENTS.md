# AGENTS.md

Инструкции для Codex и других AI-агентов, работающих с прошивкой велоспидометра.

## Цель проекта

Сделать прошивку для самостоятельного велокомпьютера на ESP32-S3. Устройство должно:

- считать скорость велосипеда по проводному датчику Холла;
- отображать скорость и данные заезда на TFT-экране;
- показывать график скорости;
- сохранять данные заезда на SD-карту;
- поддерживать старт, паузу, продолжение и завершение заезда;
- иметь тестовое меню для проверки экрана, тача, SD, USB, датчика и будущего измерителя батареи;
- подключаться к компьютеру как USB Mass Storage для доступа к SD-карте.

Текущий этап — тестовая прошивка железа и базового интерфейса. Датчик Холла и измеритель батареи физически ещё могут быть не припаяны, поэтому тестовые экраны должны корректно работать без них.

## Основной стек

Использовать:

- PlatformIO;
- Arduino framework для ESP32;
- плата: ESP32-S3-N16R8, 16 MB Flash, 8 MB PSRAM;
- экран: 3.5" SPI TFT, официально заявленный драйвер ST7796;
- тач: FT6336 по I2C;
- SD-карта: SPI, общие линии с дисплеем, отдельный CS;
- USB Mass Storage: native USB ESP32-S3 через GPIO19/GPIO20.

Не переводить проект на MicroPython. Прошлая версия проекта была на MicroPython, но новая прошивка должна быть на PlatformIO + Arduino.

## Жёсткие ограничения

### Нельзя менять распиновку без прямого указания пользователя

Все GPIO должны быть вынесены в один конфигурационный файл, например:

```cpp
src/config/hardware_config.h
```

Запрещено размазывать номера GPIO по коду.

### Занятые пины

Не использовать для других задач пины экрана, тача, SD и USB:

```text
GPIO8   CTP_SDA
GPIO9   LCD_DC
GPIO10  LCD_CS
GPIO11  SPI_MOSI
GPIO12  SPI_SCK
GPIO13  SPI_MISO
GPIO14  LCD_RST
GPIO15  SD_CS
GPIO16  CTP_INT
GPIO17  CTP_RST
GPIO18  CTP_SCL
GPIO19  USB_D-
GPIO20  USB_D+
GPIO47  LCD_BACKLIGHT
```

Датчик Холла:

```text
GPIO4   HALL_SENSOR_SIGNAL
```

Пин измерения батареи пока не выбран. В коде использовать заглушку:

```cpp
#define BATTERY_ADC_PIN -1
#define BATTERY_MONITOR_ENABLED false
```

или аналогичный безопасный механизм.

### USB и SD нельзя использовать одновременно в конфликтующем режиме

Если SD-карта отдана компьютеру через USB Mass Storage, прошивка не должна параллельно писать на SD.

Нужно реализовать явный режим:

```text
USB Mass Storage active
Device storage is mounted by host
Ride logging is disabled until USB mode is exited
```

Для первого варианта допустимо требовать перезагрузку после выхода из USB MSC, если корректное размонтирование сложно.

### Работа без SD обязательна

Если SD-карта не обнаружена, устройство не должно зависать или перезагружаться по кругу. Нужно показать экран:

```text
SD card not found
Ride logging disabled
[Retry]
[Continue without saving]
```

После `Continue without saving` все функции интерфейса, экрана, тача, датчика и расчёта скорости должны работать, но запись логов отключается.

### Работа без датчика обязательна

Так как датчик может быть не припаян на тестовом этапе, прошивка должна запускаться без физического датчика. Экран теста датчика должен показывать текущее состояние пина, счётчик импульсов и время последнего импульса.

### Работа без измерителя батареи обязательна

Батарейный монитор пока считается отключённым. В интерфейсе допускается показывать:

```text
Battery: not configured
```

## Рекомендуемые библиотеки

Codex должен выбрать конкретные библиотеки и зафиксировать их в `platformio.ini`.

Предпочтительно:

- TFT: `TFT_eSPI` или `LovyanGFX`, в зависимости от того, что проще стабильно настроить для ST7796 на ESP32-S3;
- Touch FT6336: подходящая Arduino-библиотека или минимальный собственный I2C-драйвер;
- SD: стандартная `SD`/`SPI` или совместимая библиотека;
- JSON config: `ArduinoJson`;
- USB MSC: TinyUSB/ESP32 Arduino USB API, совместимая с ESP32-S3.

Если библиотека требует отдельного конфигурационного файла, добавить его в репозиторий и описать в README.

## Правила реализации UI

- Интерфейс должен работать через тач.
- Для отладки желательно сохранить Serial-команды как запасной способ, но они не заменяют тач.
- Нижняя зона главного экрана — кнопки `Start`, `Pause/Resume`, `Stop/Finish`.
- Верхний правый угол — кнопка выхода в меню/настройки.
- Центральная область — перелистываемые страницы:
  - крупная скорость;
  - график скорости;
  - статистика заезда.
- В настройках обязательно сделать Paint-тест для проверки тача и отрисовки.

## Правила расчёта скорости

- Скорость считается по времени между импульсами датчика.
- Если нового импульса нет, использовать логику предполагаемой скорости: считать, что колесо сделало бы оборот за время, прошедшее с последнего импульса.
- Если рассчитанная предполагаемая скорость ниже 3 км/ч, считать скорость равной 0.
- Порог 3 км/ч должен быть в конфиге.
- Окружность колеса должна быть в конфиге и должна редактироваться из настроек.

## Состояния заезда

Использовать явную state machine:

```text
IDLE
RIDING
PAUSED
FINISHED
```

После перезагрузки во время активного заезда восстановить заезд в состоянии `PAUSED`, чтобы пользователь сам решил продолжать или завершать.

## Правила записи файлов

Текущая тестовая версия:

- обнаружить SD-карту;
- создать тестовый текстовый файл;
- прочитать его обратно;
- показать результат на экране;
- через USB MSC отдать SD-карту компьютеру.

Формат полноценных логов поездки будет уточняться позже. Предварительные рекомендации описаны в `docs/LOG_FORMAT.md`, но они не являются жёстким контрактом для первого тестового этапа.

## Как Codex должен работать с задачами

Для каждой задачи:

1. Проверить `docs/HARDWARE.md`, если задача касается GPIO, SPI, I2C, SD, USB или питания.
2. Проверить `docs/FIRMWARE_SPEC.md`, если задача касается поведения прошивки.
3. Вносить изменения маленькими этапами.
4. После изменений описывать, что изменено и как проверить руками.
5. Не удалять диагностические экраны ради “чистоты”. Они нужны для сборки и пайки устройства.

## Критерии готовности тестовой прошивки

Минимальный тестовый вариант считается готовым, если:

- прошивка собирается в PlatformIO;
- экран ST7796 включается и показывает главное меню;
- подсветка управляется;
- тач FT6336 работает;
- Paint-тест рисует линии пальцем;
- SD-карта обнаруживается;
- тестовый файл создаётся, читается и отображается в интерфейсе;
- USB MSC показывает SD-карту на компьютере;
- экран теста датчика показывает состояние GPIO4 и считает импульсы;
- отсутствие SD не ломает запуск;
- отсутствие датчика не ломает запуск;
- при имитации/реальных импульсах скорость считается и отображается;
- старт, пауза и завершение заезда работают хотя бы без полноценного логирования.
